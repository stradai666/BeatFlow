# Руководство по разработке BeatFlow

Братишка, если хочешь, чтобы проект не превратился в кашу, соблюдай эти правила. Это нужно для чистоты кода и нормальной работы Git.

## 🛠 Инструменты качества
Мы используем **GDToolkit** для проверки кода.
1. **Линтер (gdlint):** проверяет ошибки в логике и оформлении.
2. **Форматтер (gdformat):** автоматически расставляет пробелы и отступы.

Перед тем как делать коммит, обязательно прогони свои скрипты через:
`gdformat scripts/твой_скрипт.gd`

---

## 📝 Правила именования (Style Guide)
Соблюдаем официальный стиль Godot:

* **Скрипты (.gd):** используем `snake_case`. 
  * *Правильно:* `player_controller.gd`, `score_manager.gd`.
* **Сцены (.tscn):** используем `PascalCase`.
  * *Правильно:* `MainMenu.tscn`, `GlobalBackground.tscn`.
* **Переменные и функции:** `snake_case`.
  * *Пример:* `var current_score`, `func play_animation()`.
* **Константы:** `UPPER_SNAKE_CASE`.
  * *Пример:* `const MAX_SPEED = 500`.

---

## 🌿 Работа с Git (Git Flow)
Мы не работаем напрямую в ветке `main`.
1. Вся разработка идет в ветке `develop`.
2. Если делаешь новую фичу — создавай отдельную ветку от `develop`.
3. В ветку `main` код попадает только через Pull Request после полной проверки игры.

---

## 📂 Структура папок
Не раскидывай файлы где попало:
* Все картинки/звуки — в `assets/`.
* Все сцены — в `scenes/`.
* Все скрипты — в `scripts/`.
